# EpochMC 计分板配置示例

这套计分板由三个位置共同控制：

- `plugins/EpochCommon/config.yml`：控制标题、固定行、Nodes 归属、PAPI 变量、模块顺序和行数。
- `plugins/EpochMinerals/config.yml`：控制挖矿模块显示的文字和颜色。
- `plugins/Slimefun/epoch-rebirth-lang.yml`：控制重生模块显示的文字和颜色。

所有样式文本均使用 MiniMessage。常用格式包括：

- `<red>文字</red>`：命名颜色。
- `<#3b82f6>文字</#3b82f6>`：十六进制颜色。
- `<gradient:#3b82f6:#22c55e>文字</gradient>`：渐变。
- `<bold>文字</bold>`：粗体。
- `<gray>文字</gray>`：灰色辅助文字。

## 1. EpochCommon 主配置

下面内容可以作为 `plugins/EpochCommon/config.yml` 的完整参考。

```yaml
scoreboard:
  # 新玩家第一次加入时是否默认显示计分板。
  # 已经使用 /esb on 或 /esb off 的玩家不受此项后续修改影响。
  default-enabled: true

  # true：把玩家的开关选择写入 PDC，重启后保留。
  # false：重启后所有玩家重新使用 default-enabled。
  persist-player-preferences: true

  # 侧边栏最上方标题，支持 MiniMessage、主配置占位符和 PAPI 的 %变量%。
  title: '<gradient:#3b82f6:#22c55e><bold>EpochMC</bold></gradient>'

  # 固定页眉，始终排在业务模块之前。
  # 每个列表项占一行；空字符串也会占一行，用于留白。
  header-lines:
    - '<gray>{date}</gray>'
    - '<green>国家</green> <white>{country}</white>'
    - '<green>城镇</green> <white>{town}</white>'
    - '<green>温度</green> <yellow>%rs_temperature%</yellow>'
    - '<gold>金币</gold> <yellow>{balance}</yellow>'
    - ''

  # 固定页脚，始终排在所有业务模块之后。
  footer-lines:
    - '<dark_gray>{address}</dark_gray>'

  placeholders:
    # Java DateTimeFormatter 格式。
    # 常用示例：yyyy/MM/dd、MM-dd、yyyy年MM月dd日。
    date-format: 'yyyy/MM/dd'

    # 日期使用的 IANA 时区名称。
    time-zone: 'Asia/Shanghai'

    # Java DecimalFormat 格式，同时用于完整金币和缩放后的数字。
    balance-format: '#,##0.##'

    # true：{balance} 自动缩放为 1.5K、26M 等。
    # false：{balance} 与 {balance_raw} 一样显示完整数字。
    balance-compact: true

    # {balance} 的缩放后缀，可自行改成 k/m/b/t 或中文单位。
    balance-suffixes:
      thousand: 'K'
      million: 'M'
      billion: 'B'
      trillion: 'T'

    # Vault 或经济插件不可用时显示的内容。
    balance-unavailable: '--'

    # 玩家未加入 Nodes 国家或城镇时显示的内容。
    affiliation-unavailable: '无'

    # PlaceholderAPI 未安装、扩展未加载或变量无法解析时显示的内容。
    external-unavailable: '--'

    # 自定义静态占位符。
    # 添加 server_name: '生存一区' 后，可在标题、页眉、页脚中使用 {server_name}。
    static:
      address: 'mc.epochearth.cn'

  # Minecraft 侧边栏最多支持 15 行，更大的值也会被限制为 15。
  # 页眉、模块内容、模块分隔行和页脚全部计算在内。
  max-lines: 15

  # true：最终一行内容都没有时，移除玩家计分板。
  # 当前示例有固定页眉和页脚，因此通常不会为空。
  hide-when-empty: false

  # force：EpochCommon 始终接管侧边栏，适合服务器只使用这一套计分板。
  # yield：发现其他插件的侧边栏时让出，适合需要兼容小游戏等插件。
  ownership-mode: force

  # 周期刷新间隔，单位为 tick，20 tick 约等于 1 秒。
  # 日期、在线人数、金币和增益倒计时会按该频率刷新。
  refresh-ticks: 20

  separator:
    # 是否在第二个及后续可见模块前插入分隔行。
    enabled: true

    # 空字符串表示空白行；也可以改成分隔线，例如 '<dark_gray>────────</dark_gray>'。
    # 分隔行同样占用一行额度。
    line: ''

  # 未在 providers 中单独覆盖的模块使用这些默认规则。
  provider-defaults:
    enabled: true
    max-lines: 15
    separator-before: true

    # 空字符串表示不要求权限。
    permission: ''

    # worlds 为空表示允许所有世界；世界名不区分大小写。
    worlds: []

    # 排除列表优先于 worlds。
    excluded-worlds: []

  # 模块配置路径是：插件名小写 -> 模块 id。
  # 可执行 /esb providers 查看服务器当前注册的准确配置键。
  providers:
    epochminerals:
      minerals:
        # 是否显示挖矿模块。
        enabled: true

        # 数字越小越靠上。相同 order 时按配置键排序。
        order: 100

        # 挖矿模块最多需要 3 行：下一掉落、剩余积分、临时增益。
        # 增益未生效时第三行自动隐藏。
        max-lines: 3

        # 它是第一个可见模块时不会添加分隔行。
        separator-before: true
        permission: ''
        worlds: []
        excluded-worlds: []

    slimefun:
      rebirth:
        enabled: true
        order: 200

        # 重生模块固定最多 4 行：标题和三个等级的复活次数。
        max-lines: 4
        separator-before: true
        permission: ''
        worlds: []
        excluded-worlds: []
```

主配置可用动态占位符：

| 占位符 | 内容 |
| --- | --- |
| `{player}` | 玩家名 |
| `{world}` | 当前世界名 |
| `{online}` | 在线人数 |
| `{max_players}` | 最大玩家数 |
| `{date}` | 按配置格式生成的日期 |
| `{balance}` | 默认按 K/M/B/T 缩放的 Vault 金币 |
| `{balance_raw}` | 不缩放的完整 Vault 金币 |
| `{balance_vault}` | Vault 经济插件自身格式化后的金币 |
| `{country}` / `{nation}` | 玩家在 Nodes 中所属国家的名称 |
| `{town}` | 玩家在 Nodes 中所属城镇的名称 |

除此之外，标题、页眉、页脚和模块分隔文本支持 PlaceholderAPI 的 `%变量%`，例如 `%rs_temperature%`。PAPI 返回值会作为普通文本处理，不会被当成 MiniMessage 标签执行。

当前示例最多使用 15 行：页眉 6 行、挖矿 3 行、模块分隔 1 行、重生 4 行、页脚 1 行。所有动态内容同时出现时正好达到 Minecraft 的 15 行限制，因此不要再增加固定空行，除非同时减少其他模块内容。

## 2. EpochMinerals 模块样式

将下面片段放在 `plugins/EpochMinerals/config.yml` 中。它只控制挖矿模块自己的文字，不控制模块顺序。

```yaml
scoreboard:
  # {reward}：距离当前积分最近的下一种矿物。
  # 同一积分点会掉落多种矿物时，会显示全部名称。
  next-reward-line: '<gray>下次掉落 <white>{reward}</white></gray>'

  # {remaining}：距离下一次掉落还差的积分。
  remaining-points-line: '<gray>还需积分 <yellow>{remaining}</yellow></gray>'

  # 多种矿物同时掉落时使用的连接文本。
  reward-separator: '<dark_gray> + </dark_gray>'

  # 只有存在矿脉、指令倍率或特殊矿区倍率时才显示。
  # {multiplier}：所有有效倍率相乘后的实际倍率。
  # {duration}：下面两种 duration 文本之一。
  # {seconds}：计时增益剩余秒数；只有计时增益存在时有值。
  boost-line: '<yellow>挖矿增益 <gold>x{multiplier}</gold>{duration}</yellow>'

  # 指令增益或矿脉增益生效时替换 {duration}。
  timed-boost-duration: ' <gray>剩余 {seconds}s</gray>'

  # 只有特殊矿区倍率生效时替换 {duration}。
  region-boost-duration: ' <gray>特殊矿区</gray>'
```

EpochMinerals 当前没有独立配置重载命令，修改后需要完整重启服务器。

## 3. Slimefun 重生模块样式

修改 `plugins/Slimefun/epoch-rebirth-lang.yml` 中这四项：

```yaml
# 模块标题。
hud.section-title: '<red><bold>重生</bold></red>'

# <count> 会替换为玩家对应等级的剩余复活次数。
hud.basic-line: '<yellow>❤ <gray>× <white><count>'
hud.advanced-line: '<gold>❤ <gray>× <white><count>'
hud.ultimate-line: '<red>❤ <gray>× <white><count>'
```

修改后执行 `/erb reload`，无需重启服务器。

## 4. 生效与排错

- 修改 EpochCommon 主配置后执行 `/esb reload`。
- 国家和城镇需要 Nodes；温度需要 PlaceholderAPI 与 RealisticSeasons 提供 `%rs_temperature%`。
- 执行 `/esb providers` 检查模块配置键、顺序和实际行数上限。
- 玩家可使用 `/esb on`、`/esb off` 或 `/esb toggle` 控制自己的计分板。
- 控制台出现“因行数预算被截断”时，减少固定空行、降低模块内容，或提高对应模块的 `max-lines`。
- YAML 缩进只能使用空格，不要使用 Tab。
- 文本中包含 `:`、`#`、`{}` 或 MiniMessage 标签时，建议始终使用单引号包住整行。
- `order` 只控制模块相对顺序，不能把模块插入标题上方或页脚下方。
- EpochCommon 只负责组合模块；矿物和重生模块的具体文字必须在各自配置文件中修改。
